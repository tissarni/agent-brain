---
name: rollup
description: Regenerate a main project's _index.md from its sub-projects' frontmatter. Use when user says "rollup", "refresh index", "update project index", or after any sub-project status/summary/blocker changes.
---

Arguments: main project folder name (e.g. `web-app`). No argument → regenerate all mains.

## Token budget — this is the whole point of the skill
Reads: **frontmatter only** of each `subprojects/*/context.md`.
Stop reading each file at the closing `---`. Never read a body. Never open
`current.md`, `decisions/`, `specs/` or `_archive/`.
A main with 13 subs costs ~13 × 15 lines, not 13 × 400.

## Steps

1. Resolve `02-projects/<main>/`. Confirm its `context.md` has `kind: main`.
2. List `02-projects/<main>/subprojects/*/`.
3. For each, read frontmatter only. Collect: `project`, `status`, `summary`,
   `blocker`, `related`.
   Parsing trap: `>-` after a key means "value continues, indented, on the following
   lines". Match it as a **whole token**, never by stripping `>`/`-`/`|` characters —
   `repo: -` is a legitimate value meaning "no repo", and character-stripping silently
   turns it into an empty string.
4. Validate before writing — report, do not silently fix:
   - `parent:` disagrees with the folder it sits in, is missing, or `kind:` is not `sub`
     — all three mean a folder was moved by hand. A hand move leaves six things wrong:
     `kind:`, `parent:`, `tags:`, `related:`, a stale `_index.md` in the folder, and its
     `AGENTS.local.md` tree line; fixing only the one you noticed leaves the other five wrong.
   - `status: blocked` with no `blocker:`
   - `status: done` with no `summary.md` in the folder
   - `summary` over 160 chars, `blocker` over 120
   - `related:` naming a project that does not exist
5. Overwrite `02-projects/<main>/_index.md` with the template below.
6. Report: subs indexed, counts per status, validation warnings.
7. Last, apply the rules filed under `### /rollup` in `AGENTS.local.md` § Local rules, if there are any.

## Output template — exact
```markdown
# <main> — sub-project index

<!-- GENERATED by /rollup from sub-project frontmatter — do not hand-edit -->
<!-- YYYY-MM-DD · N sub-projects -->

> Parent context: [[02-projects/<main>/context]] · Repo `<repo>`

## Active (N)

| Sub-project | St | Summary | Blocker |
|---|---|---|---|
| [[02-projects/<main>/subprojects/<sub>/context\|<sub>]] | 🟢 | <summary> | <blocker or —> |

## Paused (N)
<!-- same table shape; omit the section entirely when empty -->

## Done (N)
| [[02-projects/<main>/subprojects/<sub>/summary\|<sub>]] | ⚪ | <summary> | — |

## Cross-project links
- `<sub>` → [[02-projects/<other-main>|<other-main>]], `<other-sub>`

---
Legend: 🟢 active · 🔴 blocked · 🟡 impl-done (written, not shipped) · ⚪ done · ⏸ paused

Read order: this file → parent `context.md` → the one sub's `current.md`. Never read a ⚪ sub's body; read its `summary.md`.
```

Section membership: Active = `active` + `blocked` + `impl-done`. Paused = `paused`. Done = `done`.
Within a section sort by status then name. Done rows link to `summary`, all others to `context`.
Omit empty sections. Omit **Cross-project links** when no sub has `related:`.

## When to run
- After `/adr` changes a sub's status or key decisions
- After a sub ships (`status: done`)
- After `/project-init` adds a sub
- Whenever a `_index.md` row contradicts the sub's own `current.md`

Never hand-edit `_index.md` — edit the sub's frontmatter and rerun this.
